## 3. 采集及写头（依赖T1—T3）

- [ ] **T5 请求内、尝试级观测通道。** 复用Ops归属与最终模型判定；最终映射/重验及实际发送/输出确认后更新，重试清理旧值，不建全局最近模型缓存，不收集正文/凭据。验收：并发、取消、恢复无串扰，决策模型不冒充执行模型；复用已有语义闸门。
- [ ] **T6 Messages 出口。** 覆盖两个 handler、原生/Bedrock、Responses/Chat/Gemini/Antigravity 桥接。分别验证早 `ping`、输出前与输出后错误、AI tool writer、SSE 顺序、终态、工具签名、思考转换和公开别名。原生与兼容实际发送模型均以请求体或 URL 为准。
- [ ] **T7 Responses HTTP 出口。** 覆盖两个 handler、原生、passthrough、Anthropic、Grok/Chat 恢复。以官方 Codex 元数据用例为基础，验证前导后 A 过载时仅 B 的可确认输出可写头；早保活已提交时，按原条件切换且保持缺头。核对加密工具参数、工具原点和账号错误策略。辅助、background、WS 验证范围隔离。
- [ ] **T8 Chat Completions 出口。** 覆盖两个 handler、`cc_pipeline`、原生 raw Chat、Anthropic/Gemini/Antigravity 桥接及 AI frame gate。对角色前导、usage-only、工具增量、`[DONE]`、SSE 注释和失败分别核对提交及重试。验证最终映射、工具 ID、终态、绑定和公开别名。
- [ ] **T9 CORS和头清理。** 合并既有Expose-Headers及拟新增项/原X-Request-ID，不放宽Origin/凭据/请求头规则；清除伪造同名值。验收：允许的浏览器可读，拒绝来源仍拒绝；重复/超长/换行/非ASCII值不注入头、不导致正常生成失败；关闭无残留；未命中路由也不能透传伪造同名值，过滤同名头时也覆盖上游声称的Connection扩展hop字段，避免代理混淆。
