# AI 路由开发计划

2026-11-05 · 本地实现及验收 · fork 基线 `main@7ba1a0a37`。用户已授权实施，产品改动保留在主工作区。本文兼作恢复入口，当前实现范围与验证记录见文末。

## 首版承诺

管理员创建「AI 路由」分组，选择决策模型，圈定执行账号、普通分组及具体模型，编写选择策略。普通用户给 Key 绑定获授权的源组，同一客户端别名可以把“整理日志”和“审查支付幂等”送到不同执行模型。返回工具结果时接回原任务。入站别名仍受源组显式白名单约束。

**普通生成模型与 Jev 同批交付，Jev 完全可选。** 全新实例只有普通账号，也能建组、预览、启用和处理请求。决策模型允许使用管理员已接入账号上的模型、自定义模型映射和兼容端点。是否可选由该账号的凭据、协议及文本输出能力决定，模型名不写死。支持纯文本的模型无需具备 JSON Schema、工具调用或概率输出能力。只提供嵌入、图像生成或尚无可用适配的通道，选择器显示原因。

本次采用首个**客户端入口**为 Claude Messages HTTP，覆盖流式、工具往返及 count_tokens 语义。它可使用来自不同厂商的**决策模型**。Chat Completions、Responses HTTP/WS、Gemini 原生客户端入口进入 M5 分别验收。首版费用由源组按执行模型计价，决策用量与费用估算单列管理员诊断。上下文默认仅发送元信息，管理员可开启受限任务文本片段。

### 已核对的 Jev 开户路径

1. 管理员进入「账号管理 → 添加账号 → TypeSafe / Jev」，填写名称和 **TypeSafe API Key**，保留默认服务基址 `https://api.typesafe.ai`。表单设为 API Key 类型、白名单 `jev-latest`，后端只接受该凭据类型。服务基址无需手填 `/v1/systemone`。普通模式可关联 TypeSafe 组或 Composite 组；未选组时后端尝试绑定已有的 `typesafe-default`。作为决策来源可设计为直接引用该账号，或选择包含它的普通 TypeSafe 分组。
2. 保存成功后账号列表重新载入，可按平台筛选并编辑；编辑时 Key 留空沿用原值。当前源码中创建表单的 Base URL、Key 两条中文提示会落到 Anthropic / Claude Console，编辑表单的 Base URL 也走共用提示。M1 修正对应语言文案并验收切换平台后的默认值，尤其是“先选 Grok 映射，再切 Jev 白名单”。
3. 账号页「测试」会发真实的 System One Noul 请求，401/403 可能把账号标为错误。**保存成功、连接成功、Choice 在指定候选中选对**分别验收。CI 用假凭据和本地模拟上游覆盖三项。当前核对为本地源码证据，真实账号状态和生产 UI 未验证。

## 两种决策器和运行契约

输入为经允许的上下文、管理员指令及本次可选编号与能力卡；输出只需一个候选编号，另记引擎、延迟、用量和可选的不确定性信息。服务端用候选快照还原执行目标。提示词与用户内容分别编码，用户不能通过指令增加候选、选择密钥或改变价格。

| 路径 | 怎样复用和验证 |
| --- | --- |
| 普通生成模型 | 按已有账号的协议规则、凭据和模型选择 Chat Completions、Responses、Anthropic Messages 或 Gemini 原生适配器。复用令牌刷新、账号代理、TLS 和必需的厂商身份头。OAuth 上游强制 SSE 时内部限时、限量收集文本；不能直接让现有 Gin handler 写入用户响应。优先验收一个兼容 API Key 通道和实际主用的订阅/OAuth 通道，再逐项验收其余凭据组合。 |
| 输出与降级 | 支持结构化输出时请求单字段枚举 JSON；通用通道可只返回短编号，例如 `c2`。两者均在本地严格比对本次候选集合。额外解释、多选、未知编号、截断、拒绝或工具事件均进入既定失败策略。禁止从长文中模糊提取模型名。普通模型自报置信度不作为准入条件。 |
| Jev | 在 TypeSafe 适配器构造原生 `state + questions`，用 `instructions` 和 `criteria` 提供任务及编号，从 `answers.route.choice` 解码。confidence 按策略选用并经样本校准。已有风控客户端解 Noul，公开 System One handler 还负责用户并发、响应和计费，只复用底层传输。 |
| 能力矩阵 | M0 的矩阵按“协议 × 凭据 × 可返回文本/结构化 × 上游流式 × 禁工具能力”列出已支持、待验证和失败原因。至少覆盖自定义 OpenAI 兼容地址、OpenAI OAuth、Anthropic API Key/现有订阅通道、Gemini API Key/OAuth/Vertex、Antigravity；按各自已有能力验证，不把一个厂商的成功外推。主用账号未通过时不得将该组合标成首版可用。 |

协议入口：[账号协议选择](../../../backend/internal/service/upstream_protocol_routing.go)、[OpenAI Chat 兼容](../../../backend/internal/service/openai_gateway_chat_completions.go)、[Gemini 协议与凭据](../../../backend/internal/service/gemini_chat_completions_compat_service.go)、[System One 服务](../../../backend/internal/service/gateway_systemone.go)、[Jev Choice 官方契约](https://docs.typesafe.ai/primitives/choice)。

1. **准入后再外发。** 源组先鉴权、校验入站别名并完成适用的外发审查和费用准入。当前静态 Composite 分派早于部分 handler 内的审查，不能原位加一次模型请求。默认只用有限的用户任务片段和元信息，预算、取消、超时、体积上限及去敏覆盖两个引擎。禁止回调公共网关、透传用户身份头和调用工具，按最终出站报文检查自动注入搜索的通道。决策与执行独立占槽；同一账号可兼任两者，先释放决策槽再取执行槽。
2. **先判续轮，再选模型。** 绑定按租户、源组、会话及工具调用/响应标识隔离，记录候选、执行模型和必要的上游账号。恢复时重验授权、目标和会话归属。无可靠绑定的专属状态请求明确失败。普通新任务可重新选择。count_tokens 须定义与执行一致的计数或明确受限行为，避免无意触发两次付费决策；流式输出开始后禁止换模型重放。
3. **先筛选，再决策，执行前复核。** 在管理员池内筛掉不满足端点、上下文、工具、图像、数据边界、已知可用状态及定价的候选。0 个返回无候选；1 个直接选；多个才调用决策器。超时、非法返回、无资格目标仅能选预设且仍合格的兜底，否则失败。调度时再查组成员和账号状态，禁止扩大原候选池。
4. **计费保留三种模型身份。** 独立记录请求别名、决策模型和执行模型。建议实际执行模型计价，源组权益和倍率决定用户支出；预留、缺价处理、退款和最终账单口径要一致。决策费记运营账，客户请求只结算一次。按请求标识关联两笔上游用量，覆盖取消、失败、重试和显式免费模型。
5. **策略发布与降级。** 建议界面独立，底层 Composite 加显式 AI 模式标识。草稿、发布版本、决策来源、候选引用及兜底整版生效。新增管理员草稿读取/保存、静态预览、试跑、启停和发布操作，引用只存 ID，不复制凭据。只增幂等 `fork_NNN` 迁移，实施前复查编号。旧程序可能将 AI 组按原静态/前缀规则处理：所有处理此组请求的实例升级后才启用；回滚先停用组并验证拒绝，或将相关 Key 转到经验证的静态组，再降级。Taom 生产操作另按既有 detached 流程执行。

## 2026-11-05 实现与恢复记录

### 管理员操作

1. 在「账号管理」添加决策来源账号。普通模型使用现有厂商或兼容端点，支持自定义映射名。Jev 选择「TypeSafe / Jev」，填写 TypeSafe Key，默认基址为 `https://api.typesafe.ai`。新建 Jev 默认关闭周期倍率探测，可显式开启；独立的账号「测试」会外发请求。
2. 在「分组管理」新建「AI 路由」。源组初始停用，创建后进入策略窗口。模式以 Composite 平台上的不可变 `fork_ai_routing` 标识持久化。
3. 选择普通模型或 Jev 引擎、指定账号或普通分组，以及决策模型。添加执行候选，每项指定真实模型、平台、一个账号或普通组、用途描述和相对成本。模型名支持手填。
4. 选择外发范围、超时和失败默认候选。默认超时 3000 ms，范围 100–60000 ms。元信息模式仅发轮数、字节数、工具和附件等信息。任务片段模式按顺序合并当前用户轮的纯文本块和相邻 user 消息，统一脱敏并限制在 2048 UTF-8 字节；不会把历史用户轮默默加入外发内容。系统提示、附件正文和工具结果正文均排除在此片段之外。
5. 「检查配置」在本地验证候选。「试跑决策」显示所选目标、用量、耗时和回退原因，按页面提示发起决策调用。只有一个合格候选时直接返回该项，并显示本次无外部决策调用。
6. 保存草稿后点击「发布并启用分组」。版本冲突保留编辑内容，重新载入需确认。修改已发布策略先形成草稿，再整版发布。复制源组生成停用副本。
7. 用户在 Key 页面选择获授权的 AI 源组，向 `/v1/messages` 发送请求。入站模型可以是任意非空别名，仍遵守源组模型白名单。用户用量按所选执行模型及源组倍率结算。

AI 源组的账号成员关系不会自动成为执行池，执行目标通过策略明确选定。OpenAI 执行候选还需源组开启 Messages 调度开关，AI 建组界面默认开启。决策来源使用 OpenAI 时独立验证自身协议与凭据。

## R3 隔离模拟整链联调（2026-11-05）

### 实际结果

- **主流程 21 项场景/里程碑通过**：先在库内 Jev 账号数为 0 时跑完普通决策，再新增 Jev。覆盖 Anthropic 执行、OpenAI Chat/Responses 转换的流式与非流式工具调用、原账号续轮绑定、跨 Key/未知工具/撤销/停用拒绝、草稿不影响已发布版本、决策失败与非法选择回退、单候选跳过决策、未开放入口拒绝和管理员元信息样例不外发正文。这里的 Responses 是执行端转换，客户端入口仍为 Messages。
- **4 项撤销/取消检查通过**：决策等待中停用策略或撤销选中账号，只有一次决策、零执行、零扣费；真实客户端连接关闭后不会延迟执行；用户及决策账号并发均设为 1 时，取消后下一请求仍可完成，证明槽位释放。
- **费用逐请求对账**：每次执行为合成的 1000 输入/200 输出 token。源组倍率 1.5、目标组倍率刻意设为 7/9；按配置的源组价格，OpenAI 执行扣费 `0.0042`、Claude 执行 `0.0105`，与用量行及余额差一致，且执行/扣费均只有一次。决策的 12/1 token 不计入用户扣费。
- **真实页面链路通过**：管理员在界面新增普通模型与 Jev 账号，留空密钥编辑后显式模拟试跑成功；AI 组检查、草稿保存、发布正常。普通用户在页面创建 Key，配合脚本只发一条模拟模型请求，用户用量页实际显示 1000/200 token 和费用 `0.0045`，余额从 100 变为 99.9955。管理员查看实际决策记录；切换 Jev 的草稿不影响旧发布，随后发布和停用成功。业务配置与 Key 创建由页面完成，请求发送由本机 API 驱动辅助完成。

### 发现并修复的问题

真实记录暴露出关联缺口：决策轨迹的 `request_id` 来自操作日志标识，用量表的 `request_id` 则使用 `client:<ClientRequestID>`，两者无法直接对账。现在保留原字段，并增加可选 `client_request_id`、`usage_request_id`，复用既有计费请求 ID 解析逻辑；页面显示可复制的用量 ID，兼容没有新字段的旧轨迹。没有修改扣费算法或新增迁移。

修复后只重建隔离后端，保留临时 DB/Redis/mock 数据。1 条独立新请求验证 `trace.client_request_id` 等于响应 `X-Client-Request-ID`，且 `trace.usage_request_id` 等于实际用量 ID；另 1 条页面创建 Key 的请求也验证该关联。Go AI/工具/计费请求 ID 专项、前端 8 项专项、类型检查和涉及文件 ESLint 通过；没有无关全量重跑。

测试脚本中修正了摘要脱敏、续轮需沿用原 public alias、OpenAI 正式协议配置三个假设，这些不记为产品缺陷。尚未进行真实模型质量、费用或延迟评测，也没有提交、推送、镜像发布或生产操作。

页面停用后再用其实际 Key 验证一次：返回 `403 GROUP_DISABLED`，模拟模型请求数、用量记录及余额均无变化。隔离代理的默认响应头缓冲不足曾导致登出 `502`，后端该次已返回 `200`；仅调大测试 Nginx 头缓冲后复验登出 `200`，保留 23 条清除 Cookie 的响应头，不改产品代码。
