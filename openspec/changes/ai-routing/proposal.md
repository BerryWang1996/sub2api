- 任意客户端模型名仍受源组白名单约束；模型选择只在管理员授权池中进行，执行和计费保留源组身份及倍率。Key、源组、目标账号与策略在决策后和实际发送前重新读取；撤销不再使用旧鉴权缓存继续执行。这是发送前最新快照，不宣称跨数据库与上游网络的事务锁。

3. **AI 五入口的续链统一严格 Key 隔离。** 保留现有 AI 工具绑定语义，新绑定增加协议/turn/lane 命名空间；非 AI Responses 继续原有同用户跨 Key 语义。通用 owner/cache 命中不能代替 AI 归属证明。Responses 控制操作的权限、方法、原账号、存储期限和终态逐项定义，不能将工具绑定的 24 小时 TTL 套给持久资源。
4. **WS 与 Gemini 保留独立协议工作。** WS 每轮重验最新 Key、组权限、策略和候选，不能仅刷新价格；先串行逐轮，再独立实现并行 lane/控制事件。Gemini 无 ID、重复同名、相同参数或并行工具结果必须有可靠的会话/调用来源证明，歧义拒绝；先实现原生来源闭环，再扩展可等价转换的公共子集。

审查结论：三模块 UI 和通用决策架构可落地，现有核心组件可继续使用；上述契约缺口先收口，再分片扩展五入口。本轮仅修订设计/计划，未修产品代码、运行产品测试或真实模型任务。

## 两种决策器和运行契约

输入为经允许的上下文、管理员指令及本次可选编号与能力卡；输出采用阶段化的有限集合：证据阶段为相关性分类编号，最终阶段为一个候选短编号或明确的拒选控制编号，另记引擎、延迟和用量。控制编号与本次候选编号不重叠，不能进入目标解析；旧模式维持仅候选编号的契约。服务端用候选快照还原执行目标。提示词与用户内容分别编码，用户不能通过指令增加候选、选择密钥或改变价格。

| 路径 | 怎样复用和验证 |
| --- | --- |
| 普通生成模型 | 按已有账号的协议规则、凭据和模型选择 Chat Completions、Responses、Anthropic Messages 或 Gemini 原生适配器。复用令牌刷新、账号代理、TLS 和必需的厂商身份头。OAuth 上游强制 SSE 时内部限时、限量收集文本；不能直接让现有 Gin handler 写入用户响应。优先验收一个兼容 API Key 通道和实际主用的订阅/OAuth 通道，再逐项验收其余凭据组合。 |
| 输出与降级 | 支持结构化输出时请求单字段枚举 JSON；通用通道可只返回短编号，例如 `c2`。执行选项严格比对本次候选集合；新历史模式额外定义互不冲突的“信息不足/歧义”控制结果，按专项失败策略处理，绝不映射成账号。证据阶段的分类编号与最终执行编号使用不同类型。额外解释、多选、未知编号、截断或工具事件均进入既定失败策略；旧模式保持原契约。禁止从长文中模糊提取模型名，普通模型自报置信度不作为准入条件。 |
| Jev | 在 TypeSafe 适配器构造原生 `state + questions`，用 `instructions` 和 `criteria` 提供任务及编号，从 `answers.route.choice` 解码。confidence 按策略选用并经样本校准。已有风控客户端解 Noul，公开 System One handler 还负责用户并发、响应和计费，只复用底层传输。 |
| 能力矩阵 | M0 的矩阵按“协议 × 凭据 × 可返回文本/结构化 × 上游流式 × 禁工具能力”列出已支持、待验证和失败原因。至少覆盖自定义 OpenAI 兼容地址、OpenAI OAuth、Anthropic API Key/现有订阅通道、Gemini API Key/OAuth/Vertex、Antigravity；按各自已有能力验证，不把一个厂商的成功外推。主用账号未通过时不得将该组合标成首版可用。 |

协议入口：[账号协议选择](../../../backend/internal/service/upstream_protocol_routing.go)、[OpenAI Chat 兼容](../../../backend/internal/service/openai_gateway_chat_completions.go)、[Gemini 协议与凭据](../../../backend/internal/service/gemini_chat_completions_compat_service.go)、[System One 服务](../../../backend/internal/service/gateway_systemone.go)、[Jev Choice 官方契约](https://docs.typesafe.ai/primitives/choice)。

1. **准入后再外发。** 源组先鉴权、校验入站别名并完成适用的外发审查和费用准入。当前静态 Composite 分派早于部分 handler 内的审查，不能原位加一次模型请求。首版默认只发元信息；任务片段及新历史模式须按已发布配置显式许可，预算、取消、超时、体积上限及去敏覆盖两个引擎和所有决策阶段。禁止回调公共网关、透传用户身份头和调用工具，按最终出站报文检查自动注入搜索的通道。决策与执行独立占槽；同一账号可兼任两者，先释放决策槽再取执行槽。
2. **先判续轮，再选模型。** 绑定按租户、源组、会话及工具调用/响应标识隔离，记录候选、执行模型和必要的上游账号。恢复时重验授权、目标和会话归属。无可靠绑定的专属状态请求明确失败。普通新任务可重新选择。count_tokens 须定义与执行一致的计数或明确受限行为，避免无意触发两次付费决策；流式输出开始后禁止换模型重放。
3. **先筛选，再决策，执行前复核。** 在管理员池内筛掉不满足端点、上下文、工具、图像、数据边界、已知可用状态及定价的候选。0 个返回无候选；1 个直接选；多个才调用决策器。超时、非法返回、无资格目标仅能选预设且仍合格的兜底，否则失败。调度时再查组成员和账号状态，禁止扩大原候选池。
4. **计费保留三种模型身份。** 独立记录请求别名、决策模型和执行模型。建议实际执行模型计价，源组权益和倍率决定用户支出；预留、缺价处理、退款和最终账单口径要一致。决策费记运营账，客户请求只结算一次。按请求标识关联两笔上游用量，覆盖取消、失败、重试和显式免费模型。
5. **策略发布与降级。** 从统一「路由」入口进入 AI 专用模块，沿用底层 Composite 的显式 AI 模式标识和既有草稿/发布机制；不要求组模式可变或改造静态路由发布方式。决策来源、文字规则、候选引用及兜底整版生效，引用只存 ID、不复制凭据。只增幂等 `fork_NNN` 迁移，实施前复查编号。旧程序可能不理解新增策略字段或将 AI 组按原静态/前缀规则处理：所有处理此组请求的实例升级后才启用新能力；回滚先停用受影响组并验证拒绝，或将相关 Key 转到经验证的静态组，再降级。Taom 生产操作另按既有 detached 流程执行。

- 保留不可变 AI 组标识及鉴权投影；本设计不涉及固定/AI 混排或模式转换。新增策略字段区分 schema 版本与编辑 revision，缺字段按首版行为读取。现有 group/Key ID、候选 ID、草稿、生效版本、状态和上下文模式无损回显；首次打开新页面不触发发布、外发或新入口启用。

### 需要明确的契约和推荐默认

1. **上下文覆盖历史，但外发由管理员控制。** 按下文专项流程实现：能放入预算时提供全部可见且获准的历史；超预算时先覆盖式分段选择原文证据，再进行最终选模。本地代码负责解析、权限、脱敏、分段、预算和引用校验，不能声称凭固定首尾截取或关键词就能判断语义相关性。旧元信息/任务片段模式保持原语义；新建组推荐显式配置长会话模式，清楚展示用户/助手可见文本的外发范围。system/developer、工具正文、附件原文和隐藏思考不自动加入。来源专属状态先恢复合法原点，不把不完整续链送给另一厂商。
2. **能力来自适配与声明，不只看模型名。** 矩阵区分客户端入口、目标协议、账号凭据、模型，以及工具、附件、结构化输出、推理状态、stream 和存储/续链能力，显示支持、不支持或未知。保留候选当前健康、限流、配额、隐私、价格和成员关系筛选；新能力未知时不能宣称可用。管理员相对成本描述不等同于真实价格或实测性能。输入 token 上限目前是字节保守界，后续不能在 UI 中伪称精准 token 计算。
3. **原点优先于重新决策。** AI 工具/response 标识按源组、用户及严格 Key、候选、执行模型、目标账号、协议与 turn/lane 记录；返回可续链标识前完成绑定，新键区分协议命名空间并兼容旧 AI 工具绑定。非 AI Responses 保持原同用户跨 Key 规则，禁止仅凭其旧 owner/cache 命中补成 AI 归属。续轮重验当前权限和目标，缺失、冲突、过期或撤销明确失败，不越池兜底。工具绑定先沿用 24 小时；持久 Response 的授权记录期限必须独立定义，不套用工具 TTL。共享 Redis 的可用性与多实例行为必须实测，进程内连接仅作连接管理。count_tokens/countTokens/input_tokens 不调用付费决策器，优先沿用已绑定或唯一合格目标；目标未定、本地估算或零值占位不得宣称精确计数。
4. **取消与费用有同一关联身份。** 保留客户端请求、运行请求和用量记录的关联；诊断增加入口、能力排除、决策与执行终态。请求取消后不得启动执行；决策超时仅可使用当次仍合格的显式兜底，已有输出不得换模型重放。已发生的用量、取消后的收尾与重试按一次结算处理。推荐继续由平台承担决策成本，用户按实际执行模型和源组倍率付费；运营侧区分实际用量、目录估算与未知成本，不用空值冒充零费用。
5. **升级不改变旧策略。** 老策略默认仅 Messages，新入口显式开启。发布保留可恢复快照；恢复旧版仍需重新校验并生成新 revision。冻结已发布 `fork_002`，如需 DDL 只新增 fork 迁移。所有实例具备新 schema/能力后才启用；降级前停用仅新版理解的 AI 策略并验证 Key 拒绝，保留数据与新增 DDL，不靠删除策略或静态回退完成降级。

### 长连续上下文决策专项审计（2026-11-05，修订设计，待实现）

**结论：原计划存在实质缺口，尚不能保证长会话语义选模。** 本轮为原方案参与者及子代理复审，不是独立实测。当前代码在新用户轮重置片段，仅发送最多 2048 UTF-8 字节；原计划也没有明确相关证据的覆盖、指代消解、阶段依赖和预算耗尽行为。以下契约替代笼统的“先用本地确定性投影找相关历史”，纳入 M5.0b，不延后到五入口全部完成之后。

#### 目标与可证明的边界

- 决策对象是**当前用户下一步要完成的任务**。相同末句“继续”，因前文是翻译还是并发排障，应允许选到不同执行候选；最新明确纠正应能改变任务，完成一段任务后换话题也应能重新选模。客户端公开模型别名只负责准入，不能代替任务语义。
- “完整”仅指本次请求实际提供、或服务端经授权能够恢复的历史，且处于管理员允许读取/外发的范围。客户端没发送、已丢弃或只以 opaque 状态保存的内容不能靠推测补齐；有限扫描预算不能承诺理解任意长度、任意层数的指代。
- **决策上下文与执行上下文分开。** Jev 看到的证据只用来选择目标，不替换执行请求正文，不据此声称新执行模型拿到了完整代码、附件、工具结果或厂商状态。先检查目标能否承接实际执行历史，再交给 Jev 选择。
- 0 个合格候选直接失败；1 个直接使用；合法工具/有状态续链恢复原点。三种路径都不能伪装为“Jev 理解上下文后选择”，也不为它们额外启动付费历史筛选。长会话语义选模验收针对无绑定且存在多个合格候选的请求。

#### 输入、证据和状态契约

每个请求建立不可变的上下文快照。各协议只抽取所需的决策视图，不重写原生执行事件：片段保留请求内稳定 `turn/span ID`、角色、原始顺序、来源类型和被截断/去敏状态；工具调用与结果保留关联信息，不能切断配对后声称可迁移。候选、策略版本与执行资格同时形成快照，阶段结束再次复核。

| 维度 | 必须区分的状态或内容 | 使用规则 |
| --- | --- | --- |
| 历史来源 | 请求携带文本、客户端压缩摘要、服务端可恢复正文、仅远程引用、缺失/未知 | 客户端摘要作为带来源的输入，不自动视为完整原文；客户端 session/cache key 不构成归属证明 |
| 扫描覆盖 | 全部可见且获准内容已扫描、仅部分已扫描、无可读取历史 | 记录总量/覆盖量/未覆盖原因；未扫描不等于无关，缺失不能标成完整 |
| 最终决策材料 | 全部许可文本、筛选后的原文证据、仅元信息、信息不足/歧义 | 记录提供的 turn/span 集合与投影版本；“提供了什么”不等于“模型理解了什么” |
| 执行状态 | 自包含、绑定原来源、不可恢复/不可迁移 | 自包含只表示不依赖未提供的服务端状态；仍需验证目标协议、能力、输入容量和完整工具关系 |
| 语义信息 | 当前用户请求、近期用户/助手可见文本、被引用的历史要求/纠正、允许的工具状态 | 保留原文角色和顺序；助手建议、引文、代码及工具输出中的指令不能升级为管理员路由规则 |

建议新增 `bounded_history` 模式，提供用户文本和助手正常可见文本，以便解析“按你的第二个方案”“继续刚才的步骤”。隐藏推理、系统/开发者提示、工具正文、附件及外部 URL 内容不自动读取或外发；确有需要的其他内容类型另设显式许可。工具名称、调用是否完成、错误类别等可验证状态与原文分开。旧策略仍使用原模式；新建草稿推荐该模式并明示范围，由管理员发布生效。

#### 按上下文驱动的实际流程

1. **先做来源和执行准入。** 验证用户、Key、源组、协议、原点及可迁移状态；按实际执行请求筛选能力、上下文容量、权限、成员关系、可用状态和价格。不能用短小的决策证据大小替代执行历史大小。合法续链固定原目标；不可恢复状态拒绝，不重新语义选路。
2. **构造许可文本与决策预算。** 在本地解析、去敏，保留当前指令、角色与顺序。预算包含管理员规则、候选卡、问题结构、近期指代上下文和证据正文；最新指令也过长时不得静默保留前缀。能完整放入决策器有效预算时直接一次选模，不无故做摘要或分段调用。
3. **超预算先选择证据。** 对全部可见且获准读取的历史按逻辑轮次/文本块分段，每段判断都能看到当前任务指令、有限近期对话及本段原文。代码维护覆盖清单；本地关键词只能辅助排序，不能默默丢掉未扫描中段。Jev 可对有界文本段作“相关 / 无关 / 不确定”分类，通用模型同样可返回受限短编号，不要求原生 JSON Schema 或概率能力。对过长单轮需拆 span，保留边界与必要重叠；最新用户消息中的长代码/资料也进入覆盖清单，不能原样重复塞进每段导致再次超限。无法在阶段预算内提供足够的当前指令/指代锚点时标为信息不足，不把任意前缀当作完整任务。
4. **收齐证据后再最终选模。** 相关及不确定片段保留为原文，加上必要相邻轮次；按原始顺序去重组装。指代仍未解析时，只允许在预先限制的追加轮次、调用次数和总预算内补查。当前任务、历史要求和后续纠正必须同时可见，不能先把旧要求机械固化成永久摘要。最终 Choice 在这一阶段之后构造，读取规则、证据、覆盖状态和合格候选卡；不能把片段问题和最终 Choice 放在同一个并行请求里假定存在先后依赖。
5. **允许明确不选。** 证据不足、任务指向歧义、覆盖不全、证据合并后仍超限或阶段失败分别返回原因。最终决策契约允许保留的控制选项 `context_insufficient/context_ambiguous`，它们不是真实候选，也不能映射成账号。默认明确失败；仅管理员显式配置时使用仍合格的默认目标，并标记为回退，不能计作正常语义选模。归属、授权、取消和不可迁移状态失败禁止走此回退。
6. **还原并执行具体目标。** 后端校验阶段输出只引用本次允许的 span/候选 ID，固定引用通过稳定 ID → 本次 Choice ID 映射。最终绑定候选 ID、执行平台、模型、指定账号/组和策略版本；指定组仍由现有调度器选择组内账号，实际账号写入执行结果。执行前重验当前策略和资格，只改必要模型/协议字段；不得把决策片段替换掉执行历史，输出开始后不得重选重放。

分段相关性判定本身也使用已配置的 Jev/普通决策来源，因此可能增加调用次数、费用和首 token 延迟；不默认引入另一个摘要模型、Embedding 服务、向量库或长期对话库。缺失、重复、非法片段编号和取消必须终止相应阶段，不能用任意字符串拼接证据。分类得到的“不确定”不能被当作“无关”丢弃；无法装入最终请求时按信息不足处理。

#### Jev 上限与全流程预算

截至本次只读核验，Jev 官方默认上限为每请求 64K、每问题 32K token；后者包括共享 state 加该问题，单个最终 Choice 也受其限制。可选长上下文头把两者提高到 262K，但官方明确提示更慢且更不准确，因此不自动开启，也不能代替证据覆盖设计。[官方模型与上下文限制](https://docs.typesafe.ai/models) 每个问题独立读取相同 state，问题间无隐含依赖。[官方说明](https://docs.typesafe.ai/introduction)

同时检查本地 task/prompt 32768 字节、input 65536 字节等现有限制；新增历史模式须统一这些限制，不能只扩大前端轮数。token 与 UTF-8 字节分别计量；无可用 tokenizer 时采用记录在适配器中的保守上界，标明估算方法，未知容量不声称精确可用。批量问题既检查各问题，又检查请求合计；不能把全部超长历史放入共享 state 再声称每问只看一个小段。

策略/服务配置必须有有限的 `max_history_bytes`、`max_history_turns`、`max_segments`、`max_decision_calls`、`max_parallel_calls`、`max_refinement_passes`、全流程 `timeout_ms`、累计输入/输出上限及每次决策请求上限。`max_decision_calls` 按实际 HTTP 尝试计数，包含重试；重试和退避共用原截止时间。校验默认配置能为最终 Choice 预留预算，至少完成一个合法路径；所有数值随策略/投影版本记录。达到任一上限便停止，不能每段重新获得完整超时或无限扩窗重试。

所有阶段共同使用原请求截止时间和取消信号，各次外发复用审查、账号并发控制及释放规则。按 request/stage/call 汇总实际用量、调用数及费用估算；不把“无独立摘要模型”写成“只发生一次决策费用”。货币硬封顶仍是独立契约，不由字节上限或事后估算冒充。固定 Jev 版本和响应实际版本记录在实施时补齐，以便重现评测；中文与中英混合代码必须单独分层验收。

#### 续轮、压缩与并发

- **可以重新选模**：客户端提供自包含的下一轮，前一个工具链已闭合，没有不可迁移引用，目标协议能完整表达执行内容。不能因为属于同一会话就永远锁定最早模型。
- **必须保持来源**：当前待续接的工具结果及其未闭合链、`previous_response_id`、有来源限制的 cachedContent/签名/opaque 状态先恢复严格 Key 下的原点。历史中完整闭合的工具调用/结果按目标协议检查可迁移性，不因此永久固定原模型。恢复“账号归属”不等于恢复“历史正文”；决策摘要不能重建这些状态。
- **无法恢复就明确失败**：工具来源缺失/冲突/撤销、WS replay 丢失、签名或缓存过期均不能静默换模型、删签名或清 previous 后续跑。客户端压缩和换窗口是可见的上下文边界，不是转移未闭合状态的许可。
- **分支独立**：同一 parent 的不同分支、WS lane、同 Key 的多个客户端分别持有不可变上下文快照与执行计划；禁止单个 `session.latest_summary/model/response` 覆盖它们。迟到结果和取消只影响对应 turn/lane。
- **复用边界**：现有 Redis 工具绑定、Responses owner 和 Gemini digest 仅能按各自契约提供原点/粘连信息。Gemini digest 是哈希，WS replay 为局部内存；都不是可查询的历史正文存储。先支持请求携带历史和合法原来源续链，不为本切片默认收集长期全文。

#### 沿用现有页面的可见性

在原「文字规则」区域显示上下文模式和范围；在 Composite 风格预览结果框及现有决策记录展开行增加来源、扫描覆盖量、提供给决策器的轮次/角色、遗漏原因、投影版本、阶段数、用量、最终候选与实际执行模型。文案用“提供给决策器的上下文”，不能把发送记录称作“模型理解了这些信息”。

离线检查仅解析管理员输入的合成多轮样例、检查预算和硬资格；超预算的语义证据筛选标为“需要决策模型”，不能伪造离线召回结果。显式试跑使用同一个正式流程，事前展示可能有多个决策调用及外发范围。合成样例可在当次操作中预览原文片段；生产 trace 只存引用/计数、版本、不透明指纹及状态，不保存提示词、完整历史、工具原文或隐藏推理，也不编造模型选择理由。

#### 验收矩阵与效果门槛

使用合成候选：`fast`（整理/翻译）、`reason`（复杂代码/并发）、`reason_dedicated`（相同模型、固定账号，规则指向紧急排障）、`vision`（图片能力）。预期以稳定候选及最终目标元组判定，不只比较模型名。每个样例分别检查决策方收到的材料、返回选择如何还原，以及执行方实际收到的历史。

| 场景 | 必须验证的结果 |
| --- | --- |
| 翻译历史与并发排障历史，末句完全相同“继续，按刚才要求完成” | 分别选择 fast/reason；最后一句和公开模型别名不能代替历史语义 |
| 同一关键事实移到长历史头部、中部、尾部，其他长度/噪声一致 | 三个位置均有扫描/引用证据，最终正确目标一致；预算内先测位置影响，超限另测覆盖状态 |
| 复杂审查后来改为只翻译；简单整理后来改为并发风险审计 | 最新明确纠正生效，两方向都覆盖；不能只固定第一任务或取最后若干字 |
| 换新话题、回到早期话题、助手列项后“做第二项” | 保留必要角色/轮次，正确恢复任务；两个同名任务且无区分信息时允许明确歧义 |
| 纠正仅出现在引文、代码或工具输出中 | 不将引用中的指令视为新的管理员策略或真实用户纠正 |
| 大量已完成工具日志/重复 JSON，当前自包含任务仍是排障 | 噪声不扩大工具正文外发；以获准语义证据选 reason，硬能力仍按实际执行内容检查；成对验证“完整旧工具链＋新独立任务”允许重选，“同样历史末尾提交待续接工具结果”必须恢复原点 |
| 真正的工具/响应续链，文本同时要求换模型 | 绑定原目标且不调用 Jev；失效则拒绝，禁止语义回退换来源 |
| 完整历史与保留关键事实的客户端压缩摘要 | 分别标明来源，目标一致性另测；压缩丢失关键任务或未闭合工具正文时不得声称恢复完整历史 |
| 仅 previous ID、WS 进程重启丢失 replay、Gemini digest/签名/cache 缺失 | owner/hash 命中不作为正文；沿合法原来源续链或明确不可恢复，禁止摘要冒充重放 |
| 候选重排、过滤无关候选、两个候选模型名相同但目标不同 | 稳定引用不移位；普通审查与紧急排障按规则得到不同目标元组 |
| 同样历史使用 auto、随机别名及貌似厂商的公开模型名 | 经源组准入后，语义选择不被别名偷换；白名单限制仍有效 |
| 历史为有效预算 B 的 25%、90%、110%、400%；规则/候选卡特别长 | 预算包含所有组成部分；扫描不全/合并证据超限明确标记，不静默截断后报正常选模 |
| 片段输出缺失/重复/伪造 ID、阶段超时、取消、阶段间策略/账号撤销 | 无未经复核的执行；最终 Choice 必须在所需证据阶段完成后构造，全部阶段预算和用量可对账 |
| 同 Key/session 的分叉、两 WS lane 交错完成或取消 | 上下文、证据、模型、绑定和费用不串线；禁止共享“最新摘要”污染其他分支 |
| 长历史中的图片/结构化/上下文容量要求 | 硬资格按原执行请求判断；仅剩一个候选时记录 single，不算模型语义选择成功 |

**模拟验收硬门槛**：上述样例及变体的解析、全范围分段调度、假决策器选中片段的原文还原、预算/去敏、ID 映射、资格、绑定、取消和用量断言全部通过；池外执行、跨 Key/分支污染、绑定续轮重选、首包后重放、原文泄露为 0。注入的标注证据在预算内不得被代码误删；这证明编排/传递机制，不证明真实模型能召回相关证据。

**真实语义验收另行授权，当前不执行**：建议至少 160 条人工预标注用例，长历史、纠正、话题切换、指代各类不少于 20 条（可多标签），覆盖中文/英文/混合代码；标注可接受目标集合和必要证据 span，避免把主观品牌偏好当标准。建议初始门槛：可判定样例目标正确率 ≥95%，关键类别各 ≥90%，相同末句成对正确率 ≥95%，必要证据召回率 ≥95%，候选重排一致率 ≥98%，头/中/尾准确率最大差距 ≤5 个百分点；至少 40 条困难样例重复 3 次并报告稳定率，目标 ≥95%。这些是拟定验收目标，不是已测能力或统计保证。

评测同时报告语义错误、歧义拒绝、非必要拒绝、超时、回退、未覆盖比例、P50/P95 延迟及全阶段成本。可判定样例的回退/拒绝不能从分母剔除以抬高正确率；故意歧义样例单独评判拒绝行为，真实工具绑定和 single 路径不计入语义准确率。冻结模型版本、规则、候选池及投影版本，先用可装入模型的完整许可历史作对照，再评估分段证据方案，定位错误来自证据遗漏还是最终选模。

#### 本轮新增的三个工程前提

1. **能力有来源，限制不能凭描述放宽。** 当前模型映射/白名单和文本模型名前缀排除不能证明工具、图像或窗口能力。M5.0a 应复用 `UpstreamModelMetadata` 及其 `Source/SyncedAt` 快照，联合适配器支持、账号/模型声明，记录来源、更新时间、冲突与未知项；快照可能混合上游和目录补充，不能统一标成账号实测。管理员限制只能收紧适配器的已知边界，不能用一句“支持全部能力”覆盖明确不支持。配置保存不自动探测上游；需要硬能力而无足够证据时不得标为已支持。[模型元数据](../../../backend/internal/service/upstream_models.go)、[账号模型准入](../../../backend/internal/service/account.go)
2. **资格必须约束最终账号。** 现有 AI 只需组内一个账号合格便保留候选；新能力要求必须贯穿候选筛选、最终调度和重试账号。可提取已有组内模态交集/最小窗口纯逻辑，或计算满足请求的账号子集，并在实际选中时重新验证。现有 `CompositeRouteAccountAllowed` 已拒绝把执行模型映射成其他名称，应直接保留。决策组各阶段可能命中不同账号和映射模型，需使用已证明同能力的子集，或逐次解析真实目标并重新核算预算，记录每次实际请求模型与响应版本。[AI 筛选](../../../backend/internal/service/ai_routing_execution.go)、[最终目标边界](../../../backend/internal/service/composite_route_scope.go)、[能力交集](../../../backend/internal/service/openai_codex_model_metadata.go)、[决策映射](../../../backend/internal/service/ai_routing_decider.go)
3. **执行窗口与决策窗口分别证明。** 在适配器内区分输入上限、输出上限及共享总窗口。对已知共享窗口检查“完整执行输入的保守上界＋输出预留＋协议开销”，转换后再查；厂商另有计量规则时按对应契约。只有 previous/cache 引用的合法续链，分别标注原点验证与容量验证：正文无法恢复时容量可能未知，由原生上游校验；要求事前硬保证的策略则拒绝未知。不能用短决策证据、请求字节或原点命中冒充完整执行容量验证。[当前独立上限检查](../../../backend/internal/service/ai_routing_execution.go)

这些是 M5.0a/0b 的实施前提，不能延后到 WS/Gemini 后才补。旧策略兼容按上节处理，不因调研自动改变其行为。

#### 准确性、速度与成本的预期

- **按规则选对，不等于任务一定做对。** 候选用途说明是管理员假设，没有自动训练或在线验证能力。规则应写清适用、不适用、冲突时偏好；先用少量用途差异清楚的候选做评测，再扩大池子。保留完整池和开放模型名能力，不硬编码排行榜，也不宣称添加模型后会自动学习其优劣。未许可的工具正文、附件或隐藏状态不会被决策器理解；只能使用已有可见文字和获准状态。低成本偏好仍是软规则，预算或权限硬限制必须由代码执行。
- **分段不是已证实优于全文。** 模型判为无关的关键纠正可能永久丢失，保留不确定片段也不能消除这种错误。新增“必要证据集全部召回的请求比例”，与逐 span 召回、证据完整时选路准确率、端到端准确率分别统计；覆盖缺一条否定/纠正即改变答案的多证据样例。各阶段分别达到 95% 不能推导整链也达到 95%。
- **拒选编号只解决表达。** Jev 官方提示 `none of the above` 在一些场景效果不佳。必须单列“应拒选却选了真实目标”和“足够信息却拒选”，不能以合法 Choice 代替语义正确性。先评测现有控制编号；不足时才比较同一最终证据上的独立适用性问题，由代码联合处理，不强制普通模型支持概率或 Noul。[官方 Choice 建议](https://docs.typesafe.ai/primitives/choice)
- **不承诺固定毫秒延迟。** 直达/绑定路径免决策；预算内有一次决策；分段有扫描调度、可能的追加阶段和最终 Choice 的串行依赖。延迟包含本地处理、账号排队、各依赖阶段内并行任务的完成时间、退避和最终选择。同组织多个 Jev Key 可能共享请求/token 限流，单请求并行上限不能保证整体吞吐；复用共享并发/冷却机制，不能在各子调用另开无限重试。[官方限流](https://docs.typesafe.ai/models)、[错误处理](https://docs.typesafe.ai/api/errors)
- **按所有实际调用算账。** 调用数＝扫描批次＋追加批次＋最终选择＋重试。2026-11-06 官方 Jev 标价为输入每百万 token $0.042、输出免费。仅按价格算术：一次累计 8K 输入为 $0.000336，分段累计 100K 为 $0.0042；这里的累计量包含重复指令、证据重读和所有有用量的尝试，是假设算例，非请求实测。失败尝试没有用量时记未知，不记零。普通决策模型按其输入、输出及适用缓存规则另算。[官方价格](https://docs.typesafe.ai/models)
- **运营收益和用户账单分开。** 总运营成本包含全阶段决策、执行、实际重试/返工及缓存差异，不能在已含缓存的实付用量上重复加算。净节省是对照方案实际成本减去该总成本，可能为负；订阅额度、账单金额和目录估算分别报告。长会话每个可重选请求重复读取历史，不能仅凭单次 Jev 单价便宣称成本可忽略；用户仍按既定实际执行模型口径结算，不把运营估算冒充用户账单。

#### 更经济的实施和验证顺序

M5.0a 先落三模块和上述能力/目标/预算契约；M5.0b 内先实现预算内完整许可历史的单次选路，建立可复现基线，再实现超预算分段和拒选，不一开始引入长期摘要库、Embedding 或额外决策供应商。两种决策引擎保留同等功能。其他入口随后复用该机制，WS/Gemini 按可证明的支持组合逐片扩展；此顺序不缩减最终五入口范围。历史 10–18 人日是首版估算，不是剩余 M5 五入口工作的工期承诺。

当前可完成的是合成样例、假上游、协议整链与账目断言。真实效果评测仍待单独授权：使用相同任务、固定版本/参数、相同候选及价格时点，比较现有静态策略、单次完整上下文决策、分段证据决策；普通模型与 Jev 分开报告。预算内样例用于全文/分段对照，超预算样例不能拿无法运行的全文方案作虚假对照，改用标注证据基线辅助定位检索错误。保留不参与提示词调优的独立测试集，避免把合成规则演示当作实际任务质量。

固定历史的只决策回放用于证据和选路指标，不能单独证明长期任务质量。获准后的端到端对照应在受控环境中，让静态策略与 AI 路由从相同任务初态出发，各自生成后续助手/工具历史；固定资源、成功判据和交互/重试上限，记录缓存条件。预先标定任务起止，以完成、失败或放弃为终点，不能把一次 HTTP 请求当成一项完成任务；“每成功任务成本”按全部尝试的总运营成本除以成功任务数，失败消耗也计入，零成功时报告不可计算而非零成本。

上节 95% 等数值保留为**候选验收目标**，不是当前预期准确率；首次基线后根据样例难度及可接受代价审定，并记录样本数、不确定区间和范围，不能事后调低目标再把同一批样例当作独立验证。除选路准确率外，必须核对最终任务通过率/返工率、每个成功任务的总运营成本、首 token P50/P95、拒选与回退率；用户可接受的质量损失和额外等待尚未给定，先报告对照差异，不自称已经实现“不降质、更便宜、更快”。

### 完成判定

五入口共同覆盖：普通决策器无 Jev 依赖；同一别名对不同多轮任务选不同候选；0/1/多候选与合格兜底；能力/定价不匹配在外发前拒绝；工具和有状态续轮原点恢复；并发发布、停用、撤销、跨实例、过期、Redis 故障；JSON/SSE/WS 的取消与首包后不重放；实际模型计费和不重复结算；普通用户权限与管理诊断隔离；旧 AI/静态组兼容和复制停用。统一页面完成三模块编辑、离线检查、显式试跑、草稿发布、冲突恢复及停用闭环。

每项标注「设计 / 已实现 / 模拟验收 / 真实效果评测」及对应证据。真实模型任务完成率、决策稳定性、每成功任务成本和首 token 延迟，待另行授权用脱敏样本评测；现有历史测试和生产健康成功不能替代这些结果。本轮只更新此计划，不新增实现或测试成功主张。

## 2026-11-05 实现与恢复记录

### 管理员操作

1. 在「账号管理」添加决策来源账号。普通模型使用现有厂商或兼容端点，支持自定义映射名。Jev 选择「TypeSafe / Jev」，填写 TypeSafe Key，默认基址为 `https://api.typesafe.ai`。新建 Jev 默认关闭周期倍率探测，可显式开启；独立的账号「测试」会外发请求。
2. 在「分组管理」新建「AI 路由」。源组初始停用，创建后进入策略窗口。模式以 Composite 平台上的不可变 `fork_ai_routing` 标识持久化。
3. 选择普通模型或 Jev 引擎、指定账号或普通分组，以及决策模型。添加执行候选，每项指定真实模型、平台、一个账号或普通组、用途描述和相对成本。模型名支持手填。
4. 选择外发范围、超时和失败默认候选。默认超时 3000 ms，范围 100–60000 ms。元信息模式仅发轮数、字节数、工具和附件等信息。任务片段模式按顺序合并当前用户轮的纯文本块和相邻 user 消息，统一脱敏并限制在 2048 UTF-8 字节；不会把历史用户轮默默加入外发内容。系统提示、附件正文和工具结果正文均排除在此片段之外。
5. 「检查配置」在本地验证候选。「试跑决策」显示所选目标、用量、耗时和回退原因，按页面提示发起决策调用。只有一个合格候选时直接返回该项，并显示本次无外部决策调用。
6. 保存草稿后点击「发布并启用分组」。版本冲突保留编辑内容，重新载入需确认。修改已发布策略先形成草稿，再整版发布。复制源组生成停用副本。
7. 用户在 Key 页面选择获授权的 AI 源组，向 `/v1/messages` 发送请求。入站模型可以是任意非空别名，仍遵守源组模型白名单。用户用量按所选执行模型及源组倍率结算。

## R3 隔离模拟整链联调（2026-11-05）

### 实际结果

- **主流程 21 项场景/里程碑通过**：先在库内 Jev 账号数为 0 时跑完普通决策，再新增 Jev。覆盖 Anthropic 执行、OpenAI Chat/Responses 转换的流式与非流式工具调用、原账号续轮绑定、跨 Key/未知工具/撤销/停用拒绝、草稿不影响已发布版本、决策失败与非法选择回退、单候选跳过决策、未开放入口拒绝和管理员元信息样例不外发正文。这里的 Responses 是执行端转换，客户端入口仍为 Messages。

### 发现并修复的问题

真实记录暴露出关联缺口：决策轨迹的 `request_id` 来自操作日志标识，用量表的 `request_id` 则使用 `client:<ClientRequestID>`，两者无法直接对账。现在保留原字段，并增加可选 `client_request_id`、`usage_request_id`，复用既有计费请求 ID 解析逻辑；页面显示可复制的用量 ID，兼容没有新字段的旧轨迹。没有修改扣费算法或新增迁移。

修复后只重建隔离后端，保留临时 DB/Redis/mock 数据。1 条独立新请求验证 `trace.client_request_id` 等于响应 `X-Client-Request-ID`，且 `trace.usage_request_id` 等于实际用量 ID；另 1 条页面创建 Key 的请求也验证该关联。Go AI/工具/计费请求 ID 专项、前端 8 项专项、类型检查和涉及文件 ESLint 通过；没有无关全量重跑。

测试脚本中修正了摘要脱敏、续轮需沿用原 public alias、OpenAI 正式协议配置三个假设，这些不记为产品缺陷。尚未进行真实模型质量、费用或延迟评测，也没有提交、推送、镜像发布或生产操作。

页面停用后再用其实际 Key 验证一次：返回 `403 GROUP_DISABLED`，模拟模型请求数、用量记录及余额均无变化。隔离代理的默认响应头缓冲不足曾导致登出 `502`，后端该次已返回 `200`；仅调大测试 Nginx 头缓冲后复验登出 `200`，保留 23 条清除 Cookie 的响应头，不改产品代码。
